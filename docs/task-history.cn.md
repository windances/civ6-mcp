**过期时间必须是可达的。** 004 和 005 最初在 T95 过期，与那些突袭任务在同一批 —— 但仅 Settler 一条线
就要跑到约 T95，所以 T95 的过期时间在设计上就让两者都不可能完成，而会话报告了这一点。004 被延长到
T105，并且实际上**在 T101 完成**了；005 是 T115，006 是 T110。在写一个终点需要生产的任务时，
**要从队列数回合，而不是从其他任务的日历数回合**。

**这份清单是机制，不是装饰。** 在一个会话已经在进行时被放入 `prompts/tasks/tmp/` 的文件，只有当该会话
重新列出该目录时才会到达它那里；下面那一段说要每回合都这样做，但没有任何东西强制执行它，而一个任务可能
好几个回合都没被读过（实测：002 在一个回合内就被捡起，而 003 和 004 直到这份清单点名它们之前，
有五个回合都没被注意到）。修改这一节会把它重新注入正在运行的会话，所以**要在添加或退役任务的同一个
提交里更新这份清单** —— 提醒承载消息，文件承载指令。

临时指令是**一个文件，而不是这份参考中的一个段落**。一个任务在它自己的 `done when:` 行成立时就算完成，
届时该文件被移入 `prompts/tasks/tmp/done/`，文件名带上回合数，上面的清单也随之更新。

- **把 `prompts/tasks/tmp/` 中每一个 `*.md` 作为本回合第一步的一部分来读** —— `get_game_overview`
  然后读那个目录 —— 并且在回合中做出某个任务涉及的决定时再读一次。不是
  `README.md`，也不是 `done/`。**循环中没有别的东西知道这些文件存在：** 它们不是可检查的规则、不携带
  任何度量，而 MCP 看不到文件系统，所以一个任务文件之所以被执行，只是因为回合循环去那里看过。空目录
  是正常状态。
- 每个文件陈述自己的范围（`scope:`）、它覆盖什么（`overrides:`）、它的可观察终点
