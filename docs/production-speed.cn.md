# 决定一座城市建造速度快慢的因素

有两类权威回答这个问题，而它们回答的是其中不同的两半。**手册**解释玩家所操作的机制（哪些公民在什么地块上工作、快乐度对产出做了什么、金币能买到什么）。**游戏自己的数据文件**决定手册从不印出的每一个数字——政策卡、总督、城邦加成、电力、忠诚度、区域成本的随进度增长。两者冲突时，**数据文件胜出**：本安装是《风云变幻》(Gathering Storm)，而 GS 重写了快乐度表（`DLC\Expansion2\Data\Expansion2_Buildings.xml:463-515`），因此手册中快乐 (happy) 与欣喜若狂 (ecstatic) 城市的 +5%/+10% 并不是游戏实际使用的数字。

下文中的路径均相对于游戏根目录（`D:\SteamLibrary\steamapps\common\Sid Meier's Civilization VI`）；`manual:NNN` 指抽取出来的手册 `.tools/manuals/manual.clean.txt` 中的某一行（它的文本抽取丢失了一些字符，因此只引用完整的句子）。

## 1. 算术

一座城市一次只朝一个项目累积生产力：

- 一个单位有"一定的 **Production Cost**，它决定一座城市必须消耗多少生产力才能生产该单位"（`manual:679`）——另外还需要一项科技，某些单位还需要一种资源；
- 生产菜单显示"**完成建造所需的回合数**"（`manual:1295-1297`）。

所以 **完成所需回合数 = (成本 - 已累积) / 每回合生产力**。剩余的生产力会滚入下一个项目，而 **用金币或信仰购买会立即建成该项目**（`manual:2111`、`manual:1275`、`manual:1279`）。下文所述的一切，要么是在移动上述某一项，要么是在绕过这个除法。

关于这个除法本身，有两点需要诚实说明：**没有任何数据文件定义溢出**——在任何 `GlobalParameters` 文件里都没有 `PRODUCTION_OVERFLOW`/结转那一行，也没有最少回合数那一行（仅有的 `*_MIN_TURNS` 行是外交那 10 回合的）；两者都在引擎侧。而且 **成本项不是一个常量**：区域是唯一一类价格随你的进度增长的项目（第 3 节）。

## 3. 生产成本——会自行变动的那一项

**区域成本随进度增长。** 区域带有 `CostProgressionModel` / `CostProgressionParam1`（`Base\Assets\Gameplay\Data\Districts.xml:44-63`）：

| 模型 | 区域 | 出处 |
|---|---|---|
| `COST_PROGRESSION_NUM_UNDER_AVG_PLUS_TECH`，参数 **40**（基础成本 54） | 圣地、学院、军营、港口、飞机场、商业中心、娱乐中心、剧院广场、工业区 | `Districts.xml:44-52` |
| 同一模型，参数 40，基础 27 | 卫城、汉萨、拉夫拉修道院、街头狂欢节、皇家海军船坞；伊坎达、书院、科通、苏古巴 | `Districts.xml:57-63`; `DLC\Expansion1\Data\Expansion1_Districts_Major.xml:9,10`; `DLC\Expansion2\Data\Expansion2_Districts_Major.xml:12,13` |
| 参数 **25**（基础 30） | 政府广场；外交区 | `DLC\Expansion1\Data\Expansion1_Districts.xml:19`; `DLC\Ethiopia\Data\Ethiopia_Districts.xml:7` |
| `COST_PROGRESSION_GAME_PROGRESS`，参数 1000 | 社区 (54)、水渠 (36)、浴场 (18)、姆班扎 (27)、运河与堤坝 (81) | `Districts.xml:53,54,58,61`; `DLC\Expansion2\Data\Expansion2_Districts.xml:15,16` |
| 无 | 市中心 (54)、太空港 (1800) | `Districts.xml:43,55` |

具体的增长算式在引擎侧；数据所陈述的是那个标记及其参数。在五个建筑文件中，**没有任何建筑或奇观带有成本增长列**——因此一个晚建的区域远比同一个区域早建要贵得多，而其他任何东西都不是这样。

其他成本侧的规则：

- **占领**：被占领城市的生产力 **-50%**（`Yields.xml:65-70`；金币 -50%，科技/文化/信仰 -75%，食物 0），增长为零（`GlobalParameters.xml:84`）；占领不是永久的（`:136`）。R&F 与 GS 改为加入忠诚度压力（`DLC\Expansion1\Data\Expansion1_GlobalParameters.xml:80,82`）。
- **游戏速度会缩放每一项成本**：马拉松 300 / 史诗 150 / 标准 100 / 快速 67 / 在线 50（`Base\Assets\Gameplay\Data\GameSpeeds.xml:22,31,40,49,58`）。
- **修复被劫掠的建筑要花费其原始生产力的 25%**（`GlobalParameters.xml:420`），而修复本身就是一个生产项目。
- **资源下限可以直接禁止该项目**：在任何地方生产它都需要 2 份该战略资源，若你拥有对应的区域则只需 1 份（`GlobalParameters.xml:551,553`）。
- **升级**：基础数据中 `UPGRADE_NET_PRODUCTION_PERCENT_COST` 是 75，被 GS 覆盖为 **100**（`GlobalParameters.xml:615`; `DLC\Expansion2\Data\Expansion2_GlobalParameters.xml:288`）。
- **军团与军队**的成本是该单位的 1.5 倍和 2.0 倍（`GlobalParameters.xml:601,603`）。

## 10. 本局中实测到的

- **一张 +1 生产力的政策卡正好值 1**：`城市规划`（Urban Planning）在 T16 被装上，该城市的生产力读数从 8 变为 9（日记 T16）。

## 11. 实际有效的顺序

1. **先打好基础**——把公民放到生产性地块上（矿场、采石场、战略资源、伐木场，以及市中心那 1 点下限），并修复或替换被劫掠的改良设施和区域（第 4 节；`manual:1401-1403`）。
2. **修好乘数的前提**——宜居度。一座低于"满足"的城市会把它的生产力乘以小于 1 的系数（第 6 节），而厌战情绪和国库为负是两个自己造成的问题来源（`manual:2155`、`2139`）。
3. **然后是百分比和固定加成**（第 4-5 节），它们以第 1 步的基础为基数进行缩放。这也是为什么 **+100% 工业区相邻加成的卡（工匠、五年计划）在相邻加成越好时价值越高**，以及为什么一座工厂值得为它有电时的产出而建，而不是为了它基础的 3 点。
4. **当项目比节奏更重要时，就绕过或爆发**：用金币或信仰购买（第 8 节），来自砍伐、大工程师次数或军事工程师次数的一次性生产力（第 7 节），以及从一个便宜项目带入昂贵项目的溢出。
5. **记住区域的那只时钟**：区域的价格随你的科技进度增长（第 3 节），因此同一个学院在 T200 比在 T50 更贵——早早锁定选址比等待完美地块更便宜。

## 12. 各因数，按它们消耗你生产力的顺序排列

第 1-9 节是算术，第 6 节是手册对这些条件的叙述。这一节是可操作清单：查什么、怎么查、以及怎么办。

**先测，而且全部都要测。** `.tools/production-audit.py` 读取每一座城市，按"此刻各自正在损失多少产能"排序，并逐城打印下面每一个因数的证据。有两条用代价换来的规则：

- **绝不把城市名、坐标或单位 id 从上一回合、上一次会话或某条笔记带过来。** 回退或新开一局会重命名每一座城、重编号每一个单位，所以**带着名字的计划是在为一块已经不存在的地盘做计划**。城市名要从眼前这次的读数里取。`.tools/_game.py` 解析当前对局；`.tools/advance-turns.py --march` 按单位"是什么"来选（`BOMBARD:28,14`），而不是按 id。
- **你没测的因数，就会被你报成"正常"。** 一个只检查了它已经注意到的那座城的审计，报出"两座城没电"；全帝国读数说是**九座**——而九座里只有一座是因为审计找到的那个原因。

### 六个因数，以及各自真正的代价

**1. 空队列。** 这座城市本回合什么都不产。这是当下最大的一笔损失，也是唯一**修复免费**的一笔。它还会阻塞 `end_turn`，所以无论你注不注意，它都要花掉一次往返。

  *怎么办：* 发现它的同一回合就填上，填那个能回答该城**排名最高因数**的项目。`.tools/production-audit.py --apply` 就是干这个的；`.tools/production-recovery.py --fill` 则不做因数排序。

**2. 被劫掠的区域。** 工业区倒下，带走的不只是生产区域，**还有它在供的电**；而且——实测——**区域没修好之前，它建筑的修复选项根本不会出现**。所以城内的顺序是**游戏强制的**，不是你选的。

  *怎么办：* 先修区域，再修它的建筑，然后才轮到该城的任何新建。修复条目自带地块坐标；**同名的新建条目不带**——这就是"只按名字查找"约有一半概率选错的原因。

**3. 被劫掠的生产建筑。** 工场、工厂、燃煤/燃油/核电厂、船坞、海港、证券交易所，以及兵营那条线。倒下的建筑产出为零。

  *怎么办：* 在任何新建之前先修。`.tools/production-audit.py --apply` 把修复排在所有其他项目之前。

**4. 没电。** 需要电的建筑在没电时**产出为零**，所以这里停摆的是研究实验室、工厂和证券交易所，不是零头。三条通道，按游戏自己的面板读法（`City:GetPower()`，`CityPanelPower.lua:42-54`）：

    currentPower = freePower + temporaryPower
    requiredPower == 0                -> 不需要电
    not IsFullyPowered()              -> 没电
    IsFullyPoweredByActiveProject()   -> 靠项目供电

  `free` 是可再生来源和水坝；`temporary` 是烧燃料的电厂，**而电厂出力同样通过 `temporary` 送到邻近城市**。陷阱在**第三条**通道：项目供的电**在两个数字里都不出现**，所以一座城可以读到 `required > 0, free == 0, temporary == 0` 却仍然"有电"。**`IsFullyPowered()` 只说这一回合，从不说明持久供给**——判据要用 `free + temporary > 0`。

  覆盖范围**不是**电力透镜暗示的 6 格。实测：距全帝国唯一那座电厂**4 格**的城市取到了电，**5 格**的没有。**覆盖要在每一局里实测**——先建一座，然后读它周围城市的 `temporary`——不要按半径规划一片。

  `City:GetPowerAdvice()` 是**模板文字**：每一座城返回完全相同的一段，连有电的也一样。它不是诊断。

  *怎么办：* 电厂被劫掠就修；否则建一座，下一座建在哪里由读数决定。

**5. 宜居度。** `amenities - amenities_needed < 0` 会按百分比扣减该城**每一种**产出，所以它和别的因数一样是生产力损失。重复的奢侈品不提供宜居度，所以多余的份数值得拿去交易。

  *怎么办：* 一个新的奢侈品类型、一座娱乐设施区域，或一张政策卡。

**6. 住房与粮食。** `housing - pop <= 1` 会让增长停止，`food_surplus <= 0` 早一步做同样的事。两者今天都不掉产能，掉的是将来——因为**增长就是区域计划**：`districts <= floor(pop / 3)`，其中政府广场和水渠免于计数。

  *怎么办：* 粮仓、水车、农场、国内商路、水渠（免于上限）、社区。**这是唯一一个真正属于"缓性"的因数。**

### 另外两个不是"状态"、但代价相同的

**空闲的区域槽**是没人取走的乘数。`districts <= floor(pop / 3)` 说这座城市允许有几个；低于这个数，就是白白留在地图上的生产力、科技或金币。

**未改良或被劫掠的地块**是干脆不存在的产出。**建造者是全局最便宜的乘数**，而站在被劫掠地块上的建造者应该**修复**它，而不是去开新的——地块已经是我们的，也已经改良过。

**闲置的商路**是没被收走的免费产出。国内商路把粮食和生产送给目的地，一条路同时解决增长和生产两件事。

### 工作顺序

1. **空队列**——同一回合，永远。
2. **修复，区域先于它的建筑**，且在该城任何新建之前。
3. **电力**——修一座电厂或建一座，并**读它周围城市的 `temporary` 确认覆盖**。
4. **宜居度**，如果有城市为负。
5. **住房与粮食**——封顶时**水渠优先**，因为它免于区域计数，且抬升幅度大于任何建筑。
6. **填掉空闲的区域槽。**
7. **建造者修未改良与被劫掠的地块**，**商人跑闲置的商路。**

### 什么时候该换掉队列，而不是等它

换掉在建项目会扔掉已经投入的锤子，所以**只对"当下就在关掉产出"的因数值得**——**没电**或**被劫掠**——而且只在当前项**剩余约三回合以上**时。住房和粮食是缓性的，而学院本身就是产出：实测，这条规则的早期版本把住房排在除劫掠外的一切之上，**一次调用里把一座 3 回合的研究实验室和一座 3 回合的学院换成了粮仓和下水道**。那是拿科技白换。现在 `.tools/production-audit.py --redirect` 用的是收窄后的规则。

有一个值得知道的例外：**已经选址的区域会保留它累计的生产力**，所以一次错误的换队列之后把区域放回去，**回合数与原来相同**。"丢了队列"和"丢了锤子"是两种不同的失败，**只有后者是永久的**。
