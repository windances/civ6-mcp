## 唯一变量：第一个攻城单位是买来的，不是造出来的

**A6 用金币买下第一个攻城单位，而不是等一个队列：`purchase_item(city_id, "UNIT", "UNIT_CATAPULT")`，而 A1-A5 是自己造出来的；第二门弩炮照旧生产，因为下面的算术不允许买超过一门。** 这个变量有两半，两半都要在记录里：金币是被**刻意攒出来**的（不买别的东西，不动用国库），然后**在一次购买里花掉**。其余全部保持不变：共享起点、设置（中国/秦始皇、王子、盘古小图、快速、两个对手）、**修正后**的 `tactics/01`（siege 2 / melee 2 / anti-cavalry 1 / ranged 4 / cavalry 1 / recon 1，撞车仅在已拥有时参战），以及战争计划。

这个变量的代价是：国库，而且不为别的东西花它。它应当买到的：第一门弩炮比 A2 的 T53 完成早四到五个回合，因为购买在金币存在的那一回合就到位，不必等队列。

`README.md` 的 A6 行把这个变量写成*"攻城序列是用金币买的，不是造出来的"*，把预测写成*"战争提前 5 回合以上开打，代价是一段 `carrying-capacity` 为负的窗口"*。下面的算术重述了这句话的后半：在这个起点上，这笔钱买的是**一门**弩炮而不是一整套序列，而战争的开打回合是跟 **A3** 比，不是跟 A2 的 T60 比（见 Q3）。

### 动手花钱之前必须先算清的账

下面这些价钱和余额都是 A2 自己的，是引用而不是重新推导；它们是本次尝试起飞前的估算，不是它的事实——**记录要在自己的位置上重新读一遍，若有不同就写明白**。

- 一门 `UNIT_CATAPULT` 造价 **120 production**，买价 **320 gold**——A2 自己在 T68 的 `get_city_production` 回执（`.civ6-mcp-data/log_china_911679432_volcanic-indigo-caravan-23.jsonl`）。
- A2 的国库：T1 6、T10 51、T20 101、T30 160.8、**T40 243.4**、**T50 274.4**、T60 229.8、T68 294.8，收入 +5.0、+5.0、+6.3、+8.9、+6.1、+8.0、+6.0 gold/turn（`docs/experiments/A2-final.json` 的 `economy` 行）。
- A2 在 **T48** 于两座不同的城各下一门弩炮，它们分别在 **T53** 和 **T55** 完成。
- A2 没有可卖的已开发奢侈资源（它 T20-T30 的日记行带着 `luxuries={}`），所以资金来源是收入而不是省钱，也不是贸易。
- 因此**在 T50 前买下两门弩炮（640 gold）在这个起点上算术上不可能**，而一门（320 gold）只是勉强够得着，预测把它放在 **T48-T50** 前后：按 A2 自己的曲线，第 320 枚金币从来不在手上过（峰值是 T68 的 294.8，T60 那行还回落到 229.8），所以窗口内的这笔购买意味着本次尝试自己的国库要跑到 A2 前面——那正是这个变量第一半的用途。记录要写明国库达到 320 的那一回合，而那个回合就是 Q2 的数字。

## 按顺序做什么

1. **先侦察**（`tactics/07` 的 Gate 0，也是修正表的侦察行）：Scout 向西、向西北，用 `get_map_area` 看地块，第一次攻击估值或 `get_staging_plan` 看池子。A6 的问题就是战争的开打回合，所以只要城够得着就行。
2. **走最短的路到工程学，并把战争城的队列留给攻城一半。** 科技落地时买而不是造：`purchase_item(city_id, "UNIT", "UNIT_CATAPULT")`，并记录回合、城市 id 和回执的 `cost=N (had M)`。这个变量的第一半是筹钱：如果国库不够，记录还差多少、以及金币越过价钱的那一回合，在等待期间什么都不买。
3. **只买一次，而且买的是第一门炮**：修正表的攻城行是 2，所以第二门弩炮照旧生产（`tactics/01` 生产顺序 1），与买来的那一门并行到位——记录要写明购买回合与当时的国库，以及造出来的那一门完成的回合。屏护是造出来的，不是买的（`tactics/01` 生产顺序 2），在第一门弩炮还没买下之前不买任何东西。
4. **后方按 `tactics/08` 的分工运转**——战争城保持军队队列，其余每座城复利，任何队列都不能空着。金币只属于那一笔购买，在筹钱窗口里不为别的花，这就是这个变量的第二半；`tactics/01` 的那个具名升级排在它后面，或者记录写明为什么没有。
5. **按 `tactics/04`/`05` 行军与集结，按 `tactics/06` 开火**：屏护在前、攻城在射程 2、最后填满开火格；宣战、当回合站位、下一回合开火，在序列能开火的每一回合都开火，同时用富余单位剪断供给线。
6. **每十回合**：写 `ESTABLISHMENT:` / `WAR READY:` / `ENEMY SEEN:`，并用数字回答 `10-TURN REVIEW` 的三个问题。按插桩解析的形状写编成行（`scripts/experiment-report.py` 里的 `SELF_REPORT_RE`）：`ESTABLISHMENT: siege a/2 melee b/2 ram c/1 ranged d/4 cavalry e/1 at T<n>`，并在旁边写上修正表另外两行，写成 `(anticav x/1, recon y/1)`。即使撞车是条件式的，`ram c/1` 这一格也要留着——没有它的行根本不会被读取——而解析器不读 anticav 与 recon，所以那两行只是报告，不计分。

## 这个项目已经付过代价的诚实条款

- **回执不是结果**：命中的攻击写过 `damage dealt:none`，攻占移动在单位已站上城格时回过 `BLOCKED`。要看之后的读取与汇总字段。
- **说清一个主张用的是哪个度量**——金币地板有三个数，彼此不一致。
- **日记与 A1-A5 共享**；插桩按会话时间归属行。
- **花在一个单位上的金币，就是没有花在别处上的金币**，所以每次购买都要记录国库，且每笔购买都要连城市 id 一起具名：`purchase_item` 自己回答 `OK:PURCHASED|<item>|cost=N (had M)`，那就是两个数字的记录，而日记自己那一回合的 `gold` 是交叉核对。
- **买来的单位并不因此豁免于编成表的计数。** 编成读的是帝国持有的单位，无论它们是怎么来的；而插桩把 `purchase_item` 当作一个生产订单，所以买来的弩炮同样填上攻城名额，并和造出来的出现在同一张订单表里。
- **被钉死的开局已经被破坏过一次**（A3：把 `UNIT_WARRIOR` 作为 T15 的第四个订单，当时钉死已经生效，`planning` 行里给了学说上的理由，却完全没提这条钉死），这就是为什么现在这条钉死带着上面那条重跑后果。
