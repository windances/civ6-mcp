# 规则该写在哪一层

这是 `AGENTS.md` 里那条路由判据的完整版，连同它背后的实测。

一条写错层级的规则就是会被跳过的规则，而本局已经实测过三次。四层，以及每层真正的用途：

| 层 | 谁读 | 它能做什么 |
|---|---|---|
| 指令（`prompts/strategies/<name>/directive.md`，作为技能的 DIRECTIVE 送达） | 会话，每次变化送一次 | 说"要什么、为什么" |
| `prompts/tactics/` 的 01-08 | 提示词点名的那位顾问，在决策点读 | 说"怎么做" |
| `prompts/tasks/tmp/` 里的文件 | 回合循环，且只因为它列出该目录 | 承载一条在册指令，带完成线 |
| `prompts/checks/turn-checks.md` | 引擎，在每一次 `end_turn` | 唯一能把回合弹回来的层 |

**路由判据，按顺序**：要什么、为什么 → 指令；会重复的做法 → `prompts/tactics/`；这一窗口的工作 → 任务文件；**凡可机械检查的，一律进 `prompts/checks/turn-checks.md`**——引擎评估的规则在达成那一回合以 `once: true` 自我退休，也不会像任务文件那样静默过期。073 就是例子：集结表是可测量的，所以它的归属是检查规则，不是文件。

## 任务文件必须带着这四样，否则会被绕过

1. **点名的第一个动作。** 实测：050 只说要拿城，得到 21 次调用、0 次 `unit_action`；053 点名了目标与头几个调用，同回合即执行。074 在册期间 T266-T278 实测 0 次 `get_target_report`、0 次占领，而 39 次生产调整与一次扫掉 50 个单位的操作干了活——直到它的三个调用被写进它自己的正文。
2. **今天就存在的触发条件。** 实测：074 要求"敌国城市"，而仅存的两个对手都读作 `war=False`，于是它在等一个没人会制造的条件，直到触发条件改成"发现"并明确授权宣战。
3. **一支正在作战的军队也能满足的完成线。** 实测：062 要求两军团都在集结点三格内，而 069 与 070 已把它们派上战场——这条对任何作战中的军团都不可能成立。
4. **从队列算得出来的到期日**，自当前回合起算，不从别的任务的日历推。

## 四条常设规则，让各层不互相骗

- **交接规则。** 一份任务的建档那一半完成时，维护那一半必须先单独发布，然后旧的才退休。实测：062 建好两个军团并在 T284 退休，补缺格的那一半随它一起走了，于是军团在无人负责的情况下衰减，直到 077 接手。
- **通道规则。** 任务文件只能通过 `AGENTS.md` 里的 `IN FORCE NOW` 那一行进循环：新增或退休任务，必须在同一个 commit 里改那一行。实测：任务曾连续五回合无人读取，直到那一行点出它。
- **张力规则。** 一份必须与教条相抵触的任务，要改教条，且两者落在同一个 commit——绝不允许悄悄分叉。实测：允许多场战争、允许同时攻击多座城市的人类指令，同时落进 `prompts/tactics/08`、任务 074 与任务 077。
- **反漂移规则。** 引用别的文档要点名到文件名与步骤，不要复述它的内容。复述就是第二份副本，第二份副本一定会过时。实测：074 被改写之后 075 仍在引用它的旧措辞；062 与 063 都已退休而 064 仍在点名它们。

**审计是一条命令**：`temp-task.py status` 回答现在生效几条、游戏在第几回合、三处来源是否一致，并把任何 `PAST ITS EXPIRY` 标出来。把它和目录清点一起，作为回合第一步的一部分。

**还有一句实话。** 指令只能告知，任务文件只能下达，两者都不能强制：引擎是会话唯一无法忽略的那一层。所以一条要紧却测不出来的规则，早晚会被跳过——本局实测了三次。保证来自指标、通道与交接；任务文件负责引导；教条负责给背景。
