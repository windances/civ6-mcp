# Civ6 编排者

只要是在操控一局正在运行的《文明 VI》游戏，就使用这套流程。

## 战略指令

本区块在应用某个战略预设时由 `scripts/use-strategy.ps1` 重写。它被注入到这里、而不是留在
`prompts/workers/` 下，是因为技能在会话开始时加载、因而确实会被读到，而 worker 提示文件
经查从未被查阅过。

<!-- DIRECTIVE:BEGIN -->
中国，秦始皇（大一统者）。要围绕这个领袖真正拥有的两个能力来打，而不是一套通用的征服计划。

**Dynastic Cycle（文明能力）。** 尤里卡和鼓舞的价值是 60% 而不是 50%，并且完成**任何**奇观都会
给予一个来自该奇观所属时代的随机尤里卡和一个随机鼓舞。因此对中国来说，奇观就是一座
*科研建筑*。

- 在研究一项科技或采纳一项市政之前，先说出加速它的那个尤里卡或鼓舞，以及触发该加速的动作。
  中国从一次加速中得到的收益超过任何其他文明，所以跳过加速就是在浪费这个能力。
- 有意识地建造廉价的上古时代和古典时代奇观，为了那些加速，即使它们自身的效果很有限。
- 长城段落由 Builder 建造，而不是由城市建造：它们不消耗城市产能，并沿边界回报金币、文化和
  防御。要把 Builder 富余的次数花在长城段落上，而不是让次数白白过期。

**Crouching Tiger（特色单位）。** 中世纪远程单位，射程 1，战斗力高。射程 1 意味着它必须紧贴目标
站位，所以每个 Tiger 都要配一个近战单位占住它正前方的那一格。它是中世纪防线以及任何攻城作战的
骨干。

**Thirty-Six Stratagems（领袖能力）——需要人类协助。** 一个近战单位可以把相邻的蛮族单位转化到
我方，代价是该近战单位本身。MCP 接口没有为此暴露任何动作，所以智能体无法触发它。

- **蛮族营地是一个目标，而且它要被武力摧毁。**（人类指令，2026-09-26：本条规定取代了早先那条
  "不要清剿蛮族营地"的规则，那条规则只把营地看作可转化单位的储备池。）营地没有 HP、没有城墙，
  也没有驻军加成——**一个军事单位移动到它的格子上就能摧毁它**——所以问题从来不是它能不能被杀掉，
  而是走进去的那个单位能不能活过守军。先跑 `prompts/tactics/07-pre-war-analysis.md` 的**营地关卡**：
  清点两格内的每一个蛮族单位及其类别与 HP（C1），读营地所在格的地形以及最后一步的代价（C2），
  选出**两个**攻击者：一个克制单位，加一个尚未行动的走位单位（C3），确认走位是从我们已经控制的格子
  出发（C4），权衡金币/时代得分/`CIVIC_MILITARY_TRADITION` 鼓舞与被从计划中抽走的单位（C5），
  并说明哪座城市让出它的驻军（C6）。面对蛮族的 **Spearmen**（反骑兵）时，这意味着远程火力加一个
  近战单位走进去——绝不要让骑兵撞上长矛，绝不要让 Scout/Builder/Trader 接近营地。
- 蛮族单位随时代升级，所以一个未清剿的营地会不断在我们的城市旁边产出与当前时代相称的单位。
  这种刷兵正是清剿它的理由，而且这是有实测的：(60,30) 的营地产出了 (60,29) 的 Spearman，
  迫使我们在 T65 花 160 金币购买了一个 Warrior。不要路过任何位于某座城市或某个 Builder 的
  作业点三格以内的营地。
- 领袖能力 Three-Six Stratagems 可以转化相邻的蛮族单位，但只能从游戏 UI 里操作——适配器没有暴露
  动作。所以**在摧毁营地之前，先报告任何站在我方近战单位旁边、且其类型值得转化的蛮族单位**，
  好让人类先把这次转化打出来。不要让这件事拖延突袭，也不要为了当转化农场而留着营地不杀：
  人类的指令是摧毁它。
- 把出现的任何被转化单位都当作免费增援：它没有花费 Iron，也没有花费产能。

**常规军队，也就是智能体真正会造的东西。**

- 开采边界内的每一种战略资源，尤其是 Iron 和 Niter。绝不要把计划建立在进口资源上：你一宣战，
  那笔交易就结束了。
- 在产能最高的城市建 Encampment 和 Barracks。由于智能体没有一条不依赖资源的建军路线，
  单位生产时间就是那个硬约束。
- 近战负责夺城，远程负责削弱，攻城器对付城墙。没有攻城单位就绝不攻击城墙，并且只在胜算有利时
  进攻。
- 让受损单位治疗，而不是把它们往前送。

**行军途中的接触——用克制单位处理挡路的东西。**

- 在突击部队集结或行军期间，**任何站在我方单位两格以内的敌方单位都要在当回合处理掉，然后纵队
  才能继续前进。** 从敌人旁边走过去，意味着同一回合里既要从正面承受城市的远程打击、又要被绕过的
  那个单位从背后打，而最先死的就是攻城车队。检查规则所强制的正是这件事的可度量形式：
  **不得留下未使用的合法攻击**（`use-your-attacks`，读 `skip_remaining_units` 打印的
  `UNUSED ATTACK` 行），以及**接触要求集中兵力**（`mass-on-contact`：进入射程的是我方两个单位，
  而不是一个）。
- 挑代价最小的目标：**先补掉受损的单位**（`weakest_enemy_hp_within_2`），然后是威胁最大的那个——
  敌方的攻城或远程单位比一个侦察兵值钱，能一次打死的单位比只能打掉一层皮的更值。
- **有克制单位时优先用克制单位**（`enemies_cavalry_within_2` 之类来自游戏自身的
  `PROMOTION_CLASS_*`，而不是来自一份名字清单）：
 - **反骑兵**（由 Bronze Working 解锁的 Spearman、Pikeman）对付**骑兵**（Horseman、Knight、
   Heavy Chariot）。骑兵会无视前线，吃掉攻城车队和它身后的远程线——Spearman 是现成的最廉价解法。
 - **远程**对付**近战**：远程不受反击，所以远程单位可以一点点磨掉一个近战堆，而不给对方治疗的
   回合。
 - 我方**骑兵**对付**远程、攻城单位和平民单位**：它能越过掩护直接够到目标，而不是和掩护互换伤害。
 - **近战**对付**反骑兵**；**攻城器**只用来对付城市。攻城单位面对单位几乎毫无还手之力——
   绝不要让它占住前排那一格。
 - 当射程内还有受损单位时，不要把远程攻击花在一个满血、你又杀不掉的单位上。
- **在集结期间，接触的代价不止于战斗本身，所以要把这件事交给正确的单位。** 敌人是对着纵队宣战的，
  而不是等纵队集合完毕：T103 Russia 宣战时，我军距离它的集结行还差两回合，T104-T106 都花在清理
  接触战场上了——一个 Nalanda 的 Warrior 走上了发射位，用了三回合、四个攻击者才拔掉——于是对
  Moscow 的第一轮齐射从 T105 推到了 **T107**。这在实践中的含义是：**由掩护线（近战、反骑兵、
  骑兵）去应对接触；射手从它已经站着的格子上开火，要有 LOS，绝不在接触回合走到射击位**
  （T105 就是这样丢掉了一个 12 HP 的击杀——下达的射击回复 `NO_LOS`，重试时反而把单位走位了）；
  以及**落在敌人手里的环形格要夺回来，而不是绕开它**——纵队可以改道，射击环不能。完整流程见
  `prompts/tactics/04-staging-out-of-range.md` 第 5 步。
- 例外情况，而且必须写下来：一个落单的侦察兵，或者一个我们刻意留着、以便用 Thirty-Six Stratagems
  转化的蛮族单位，可以不管——在日记的 tactical 行里说明，这样这次被跳过的攻击就是一项决定，
  而不是一次疏漏。
- **"待命"不是一个拥有未使用攻击的单位可以被留在的状态。** 一个还有移动力、也有合法目标的单位，
  要么进攻，要么带着理由被明确按住；`metric(unused_attacks) > 0` 会让 `use-your-attacks` 规则失败，
  而收尾回合的 skip 调用现在会精确打印出是哪些单位把一次攻击扔掉了。一个"留作夺城单位"的单位
  （T109 到 T116 期间位于 (53,36) 的 Heavy Chariot）仍然是战斗单位：留着它并不意味着可以放任那个
  杀掉我们 Battering Ram 和一个 Warrior 的敌人带着 7 HP 到处走。
- **HP 在 20 或以下的受损敌人必须在当回合死掉**（`finish-the-wounded`）。在城市里或晋升之后，
  它一回合大约治疗二十点，所以放过它不是拖延，而是重置。射程内的一个远程单位就能免费杀掉它。
- **在判定一个单位不行之前，先测一下这对组合。** Catapult 对 Russia 的 Swordsman 只打出 8 点伤害
  （T109），原因在于那个单位有 **Battlcry** 晋升（`PROMOTION_BATTLECRY`：*对近战和远程单位*
  +7 战斗力），这就是为什么面对我方远程火力时那个 Swordsman 读出来是 CS 42。那个加成不适用于骑兵
  攻击，所以 Heavy Chariot 面对的是 CS 35 而不是 42——而这件事从来没有被估算过一次。每对组合估算
  一次，然后决策；不要把某一个单位的糟糕结果推广成"整支军队都没法打这个"。

**围城。**

- **首先是队形：在敌人够不到的地方集结，掩护线在前，远程和攻城器在后。** 城市的远程打击够到两格，
  Catapult 也一样；城市能吸收对方的回击，Catapult 不能。所以：
  1. **在他们射程之外集结**（距目标以及任何敌方单位三格或更多）并在那里列阵。回合结果里的
     `SIEGE POSTURE` 会按攻城单位逐一报告：到最近可见敌方单位的距离、该敌人到距攻城单位最近的
     前线单位的距离，以及到最近可见敌方城市的距离。
  2. **能挨打的单位站在前面**——近战、反骑兵、骑兵——远程和攻城单位站在它们身后。检验标准不是
     "附近有没有东西"，而是"有没有东西**比攻城单位更靠近敌人**"：`metric(siege_exposed) > 0`
     会让 `screen-the-siege` 失败，而一个距目标只有 1 格的 Catapult 已经输了。
  3. **尤其要保护 Catapult 所在的那一格。** 它是这堆单位里最贵的，也是最扛不住被集火一回合的。
     如果掩护线到不了它前面，Catapult 就留在后面——绝不与城市相邻，绝不做离敌人最近的那个单位。
  4. **只有列好阵才推进。** 一个单位一个单位地走进去，正是攻城车队被各个击破的方式；要一起到、
     成队形到，并在同一回合开火。
  5. **在路上，接触规则优先于时间表**：一旦某个单位发现敌人或遭到攻击，先评估、集中、歼灭，
     然后再继续推进。城市是有耐心的；一个从敌人旁边走过去的 Catapult 没有。
- 要在战争*之前*组建攻城车队，而不是在战争期间。这局游戏里一场 170 回合的战役造出了**零个**
  攻城单位：St. Petersburg 的 100 点城墙大约每次弩手攻击掉十点，这座城市花了十回合。远程火力
  不能替代攻城器。
- 这条升级线连同数字：Catapult 120 / CS 25 / **对城市 45**（Engineering，不需要资源），然后
  Trebuchet 200 / CS 35 / **45**（Military Engineering，不需要资源），然后 Bombard 280 / CS 45 /
  **55**（需要 Niter）。那个对城市伤害的数值是专门的轰击值，所以它不承受远程对城墙的惩罚——
  Trebuchet 破墙比任何 Crossbowman 都快得多。
- Battering Ram（65）和 Siege Tower（100）属于 `FORMATION_CLASS_SUPPORT`：它们与近战叠加，
  并且只在紧邻城市的那一格上生效。Ram 让进攻的近战单位对城墙造成全额伤害；Tower 让它们无视城墙、
  直接打城市。这两个能力都**只对近战**有效——在它们旁边攻击的远程或攻城单位什么都得不到，
  所以一座停在你的 Crossbowman 旁边的 Tower 完全没有在工作。**两者都在
  `CIVIC_CIVIL_ENGINEERING` 时过时**，而且**我们两个都不造**（人类指令 2026-09-26：不要 ram，
  用 Catapult）——但**我们手上已有的那个 ram 要跟着走**：它是支援单位，所以它随近战单位移动，
  并站在紧邻目标城市的那一格上，让它们的攻击对城墙造成全额伤害（人类指令 2026-09-26：如果 ram
  已经是我们的，就让它参战）。已有的资产要用起来，第二个不买，Tower 一个也不造。只有在有城墙可破的
  地方才值得带上它：先读目标的 `walls`（城市那一行会打印 `walls none` 或具体数值），因为在被放弃的
  那条分支上，每一座 Russia 城市都读作 `walls 0/0`，拖着 ram 走的十七个回合什么也没做成。
- 如果战争已经开始而你还没有攻城车队：不要用远程攻击去磨一座有城墙的城市，也不要把 ram 当作攻城
  单位的替代品。下单攻城单位并接受等待——先检查产能估算，不要为一座你两回合就能拿下的城市下一个
  需要 10 回合的 Trebuchet。我们手上的 ram **只对近战打城墙有帮助，别的什么也不帮**，所以等
  Catapult 仍然是正路。
- 每回合的工作顺序：攻城器把城墙打到 0，近战（跟在 Catapult 火力之后，城市有城墙时让 ram 在旁边）
  夺城，**远程打城市的 HP**。不要把远程攻击花在你已经有攻城器对付的城墙上。**远程攻击永远不能
  占领城市**——城墙归零之后，城市只会因为一个近战单位走进去而陷落，所以从远处对着城墙为 0 的
  城市开火的回合，就是没有用来终结它的回合。
- **驻军待在城市里时不要瞄准它。** 手册（`GARRISON UNITS IN CITIES`）说得很明确：驻军单位的一部分
  战斗力会加到城市上，城市被攻击时驻军单位**不受伤害**，只有城市陷落时它才会被消灭。受到伤害的是
  城市：先是城墙，然后是它的 HP 池。驻军一旦走出来就立刻成为目标——而如果它从城内发起攻击，
  城市就会失去驻军加成，那一回合就是狠狠打它的时候。早先教条里那句"远程打驻军"是错的，也正是它
  导致八个回合的火力跟一个从未掉过 HP 的单位互换伤害。
- **占领是与造成伤害分开的一步。** 当城市的 HP 池读数为 0 时，必须**在同一回合**让一个近战单位
  移动到城市所在的格子：城市一回合大约治疗二十点，所以一座被打残的城市放着不管，六个回合后就回到
  120/200，整轮轰击全部白费。回合结果会带一个 `TAKE THE CITY` 区块，指明那个格子和射程内具备占领
  能力的单位；当一座 0 HP 的城市还立着、旁边明明有一个可占领单位时，`take-the-city` 会失败。
  近战、反骑兵**以及骑兵**单位都能占领城市——Battering Ram 或 Siege Tower 会被 `CAPTURE_MOVE`
  BLOCKED 拒绝，远程和攻城单位也不行。在 T122 之前这里一直把骑兵列为无法占领，直到一个
  Heavy Chariot 走进 0/200 的 Moscow 把它拿下，而扫描还说那格是空的。
- **切断补给线，而不是硬拼治疗量。** 手册（`HEALING DAMAGE TO CITIES`）：城市"只要还有补给线"
  就会治疗，而补给线是"任何与城市相邻、且不在敌方单位控制区内的格子"。所以治疗是有条件的，
  一支占住（或守住）每一个相邻格子的军队可以直接让它停下来——这比想办法每回合多打出二十点伤害
  便宜得多。`SIEGE PROGRESS` 区块会报告这个计数（`supply line 4/6 cut`），而城墙只能通过生产
  队列修复，而且只有在连续三回合没有受到伤害之后才行。
- 一座**没有驻军单位**的敌方城市仍然是合法目标：照常攻击那个格子（适配器会解析为城市本身）。
  一座空城不是打不了的城市——它是一座可以进去的城市。
- 攻打一座城市需要什么：**3 个 Catapult（每座城市三个 Catapult，人类指令 2026-09-26）**、
  2 个近战、4 个远程（2 个射程 2 的 Crossbowman 和 2 个射程 1 的 Crouching Tiger）以及 1 个骑兵
  用来清残。**不要 Battering Ram，也不要 Siege Tower**（同一份指令：不要 ram，用 Catapult）——
  Catapult 才是破墙者：无论有没有驻军，它对城市打出 45-52，而 Archer 打 CS 35 的驻军只有 9-11，
  城墙倒下之后近战再走进去。三个一起开火实测对一座城市**每回合约 260**（Moscow T123：两个
  Catapult 一回合打出 174），这正是让围城对一座每回合治疗约二十点的城市保持有界的原因。
  我们手上的那个 ram 在目标有城墙时**加入突击**（人类指令 2026-09-26：如果 ram 已经是我们的，
  就让它参战），作为近战单位的支援单位；它不是必需条件，第二个永远不会造，Tower 一个也不造。
  每个 Crouching Tiger 都需要一个近战单位占住它前面的那格。
- 用城市自己的数字来评判一次突击：结果行上的 `city hp: N/200` 和 `walls: N/100`（或 `none`），
  而绝不是伤害估算——在城市格上，那个估算描述的是站在那里的单位，一个非战斗人员会让它读出一个
  毫无意义的 `~0`。对城市的每一次命中也会记录它的 HP，回合结果会带一个包含差值的 `SIEGE PROGRESS`
  区块；在连续三个有记录的回合没有净下降之后，它会说 `SIEGE STALLED`。城市一回合大约治疗二十点：
  如果突击打出的伤害没有超过治疗量，就停下来修好它（攻城器就位并受到掩护、对同一个目标投入更多
  攻击者），或者干脆收手——并在日记里说明选了哪一个。
- 城市的远程打击够到 2 格。不要从 3 格外下达 `city_attack`，也不要零零碎碎地把攻城车队送上去——
  要在宣战之前把它集结到目标旁边，而不是之后。

**三个阶段，适用于每一座城市和每一个蛮族营地（人类指令 2026-09-26）。**
任何目标都不会在被发现的那一回合就遭到攻击，也不会从军队恰好站着的地方发起攻击。每一个目标——
一座敌方城市、一次用征召部队执行的突袭，或者一个蛮族营地——都要按这个顺序走过同样的三个阶段，而日记要说明
这一回合处在哪个阶段：

1. **战前分析——`prompts/tactics/07-pre-war-analysis.md`。** 在投入之前用目标自己的数字读懂它
   （城市：驻军 / 城墙 / HP 池 / 环形格；营地：两格内的守军、地形、接近路线），并跑完各个关卡——
   城市五关，营地 C1-C6。触发条件是目标**正被攻击**：我们不需要在进攻前掌握每一座城市的信息，
   这一点依然成立，而把地图上每一座城市都读一遍并不是一个关卡。
2. **突击前的集结——`prompts/tactics/04-staging-out-of-range.md` 第 3b 步，由 `get_staging_plan(x, y)`
   针对目标自己的格子生成。** 营地的格子与城市的完全一样对待：环形格、路径和按不同格子的分配都
   相同，回复会点名对象（`STAGING PLAN for the camp at x,y`、`WALK-IN OPENS`），每个单位一行，
   到达回合来自游戏自身的寻路，而**最后一个**射手就位的那个回合就是时间表。在只有一个单位宽的
   走廊里，每次调用只下达一次移动，并在两次之间重读 `get_units`。
3. **突击执行——`prompts/tactics/05-formation-and-screening.md` 和
   `prompts/tactics/06-assault-composition-and-fire.md`。** 攻城器砸墙，远程打 HP 池，近战和骑兵
   夺格，前线在前、攻城器在后方射程 2 处。对营地来说，最后一步是对一个没有 HP、没有城墙也没有
   补给线的对象走位——一个军事单位**移动**到那一格上，而敌人是守军，不是营地。

这些阶段不是可选的，也不能重排，它们的代价是有实测的：T159 下达了八次编组移动命令，却只把八个
单位中的**一个**放到了 Kazan 的环形格上，而从来没有一个 Trebuchet 向那座城市开过火，因为车队
从未集结——这些阶段之所以存在，是因为从内部看，跳过其中一个就是这个样子。`prompts/tasks/tmp/` 里
的任务文件为需要目标的行动补上*目标*；它们从不替代任何一个阶段。

**发展。**

- 四到六座城市，然后停止扩张。绝不在规模为一的城市里训练 Settler。
- 在第一次战争之前保持宜居度为正：战争疲劳恰恰会在军队最需要产能的时候压制产能。
- 建 Commercial Hub 或 Harbour，因为单位维护费随军队规模增长。
- **专业区域受人口限制：`districts <= floor(pop / 3)`**（游戏的
  `DISTRICT_POPULATION_REQUIRED_PER = 3`；Government Plaza 和 Aqueduct 不计入其中）。每次选择
  生产内容时都算一遍这个算术，并且永远不要留着一个空着的区域位——增长*就是*区域规划。一个实例：
  Changsha 在人口 3-5 上带着一个未使用的区域位坐了 30 个回合，而首都从头到尾没建过一座 Campus。
- **Builder 是游戏里最廉价的倍增器，而未改良的格子是一个帝国停滞的常见原因。** 在同一局里，
  那个帝国在 T59 有 35 格和**2 处改良**，一个邻居的首都在光秃秃的丘陵上以 1.8 产能坐了一百个
  回合。如果金币大约在 300 以上而任何城市还有未改良的格子，就买一个 Builder，而不是攒钱去买
  15 回合之后的什么东西。超过约 300 的金币，如果不是为了在某个指定回合做某笔指定采购而攒着，
  就是一种被浪费的资源。
- **城市内的建造顺序：** 先增长（Granary、Water Mill、农场），然后一座 **Campus**（科技会复利），
  然后 Commercial Hub，然后 Government Plaza，最后只有战争确实临近时才建 Encampment。Campus 排在
  军队之前，而不是之后。
- **住房是硬性停止点，不是警告。** 如果 `housing - pop <= 1`，这座城市即将停滞几十个回合；现在就
  用 Granary、农场、Aqueduct 或一条国内贸易路线修好它。在淡水旁建立新城市。
- **除非你确实在抢一个 Great Prophet，否则不要建 Holy Site。** 池子很小而且很早就满了——在那局
  游戏里五个名额在 T151 前就都没了——而一个无人认领的 Holy Site 之后整局游戏每回合大约只产一点
  信仰。那是一个白白花掉的专业区域位，而它还是那个帝国的*第一个*区域。
- **军队预算：** 把单位维护费控制在大约收入的 30% 以下，并把**负 GNP 当作军队造多了的硬信号**。
  一支庞大的军队不是战略——在有了攻城车队和一个指定目标之前，它只是一项成本。实例：军事
  20 -> 101 -> 273，同时区域从 0 -> 4 -> 6，金币变成每回合 -132，而那些单位为的那场战争仍然
  打了 60 回合。
- **对中国来说奇观就是一座科研建筑**（见上文 Dynastic Cycle）：每一个都给予一个尤里卡*和*一个
  鼓舞，而中国的加速价值 60%。在古典时代就把第一个廉价的建起来：等到 T170 才造 Oracle，等于把
  整局游戏的这一能力扔掉。

**发展与征服之间的平衡。**

这个平衡点不是和平回合与战争回合的比例，也不是一种关于军队该有多大的感觉。它是三个你可以在棋盘上
检查的条件。

- **发展永不停止，包括在战争期间。** 改良、增长、Campus 这条线、宜居度和一座奇观是复利引擎；
  军队在实际开始夺城之前纯粹是成本。**"粗放"才是关键：在宣战时把城市分工定一次，不要每回合重新
  规划分工。** 一座城市——产能最高的那座——是战争城市，负责造单位、攻城器和 Encampment；
  **其余每一座城市在战争期间只建它的下一个区域或该区域的建筑，别的什么都不建。** 在 T103-T130 的
  Russia 战争期间实测，账本显示的正是这种分工：区域 5 -> 16，改良 20 -> 30，科技 32.3 -> 57.3，
  领土 58 -> 122——全都在战争**期间**，而金币/回合从 34.8 掉到 0.4（下降 99%），
  `carrying-capacity` 从 T111 起在剩下的十九个回合里一直失败。这两条线并不矛盾：**产能复利增长，
  收入供养军队。** 战争给后方带来的代价是单位和金币，而不是区域——反例就在同一本账上：Changsha
  带着一个空着的区域位坐了三十个回合，首都在没有 Campus 的情况下进入了中世纪。
- **战争不需要的单位也仍有工作。** Builder 要继续产出并远离前线（Builder 的战斗力为零）——那场
  战争期间 +10 处改良正是让 `builder-backlog` 通过的原因。贸易路线从不空转；它们的容量来自那些在
  做复利的城市正在建的 Market 或 Commercial Hub，所以这两半互相供养。只有当一个 Settler 能拿到
  军队需要的战略资源时，它才是战争目标：Iron Working 在 T104 研究完成，而 (60,32)/(57,42) 的
  iron 到 T130 仍未开采，所以那场战役里始终造不出 Swordsman，也造不出 Knight，同时马的存量卡在
  50/50、每回合丢弃 +2。每座城市恰好一个驻军，取自最廉价的闲置单位。
- **总督是用来买阶段的，而调动一个是免费的。** Victor 放在被占领或忠诚度低的城市（Moscow 有他在
  时保持 33 忠诚度、每回合 -1.9，没有再叛乱）；发展时期把 Pingala 放在人口最高的城市（Researcher
  每人口 +1 科技，在这个阶段比任何建筑都值）；把 Magnus 放在生产 Settler 的城市。完整流程，
  包括回合紧张时的优先顺序和需要报告什么，见 `prompts/tactics/08-war-and-the-home-front.md`。
- **按目标城市来定军队规模，而不是按一个目标数字。** 更多单位不等于更多征服：那个 170 回合的帝国
  达到了军事 596，战争仍然打了 60 回合，因为它造出了**零个**攻城单位。一堆无法在有界回合数内破墙
  的单位是一张账单，不是一种威胁。
- **把军队保持在经济能承受的范围内。** 付完它的账之后，`gold_per_turn` 必须仍然在 +10 左右或更好。
  这个上限是可以量出来的：那个帝国在 T60 到 T120 期间维持军事 91-241，金币每回合从未低于 +17，
  然后在 T150 前把军队几乎翻倍到 592，金币每回合掉到 +0.6——45 个回合的收入交给了维护费，为的
  是一场已经停滞的战争。它的承载能力大约是军事 **250-300**。军事 596、每回合 -0.1 金币，并不比
  156、+19.8 更强；它只是更慢。如果预测会让金币/回合掉到 +10 以下，那么错的是军队规模或战争长度，
  **绝不是后方**——而金币/回合正是在 T103-T130 那场战争里唯一没有恢复的数字。

所以唯一重要的决定是什么时候开始，而触发条件是一份清单，而不是一个回合号：

1. 一个指定的目标，其城墙和驻军能在有界的回合数内被打破。
2. 攻城车队已经在它旁边集结完毕——**每座城市 3 个 Catapult**、2 个近战、4 个远程、1 个骑兵、
   **不要 ram 也不要 tower**（人类指令 2026-09-26：不要 ram，用 Catapult，每座城市三个 Catapult）
 - **在宣战之前**，而不是宣战之后再排进队列。
3. 宜居度为正。战争疲劳在战时每回合消退 50，和平时期是 200，而 400 点会消耗一点宜居度，
   所以一场长战争压制的正是为它买单的产能。
4. 把军队算进去之后，`gold_per_turn` 仍然在 +10 左右或更好。

中国比大多数文明更把天平倾向发展：中世纪之前没有特色单位，所以不存在军队强得不成比例、随便一波
快攻就能占便宜的早期窗口；Dynastic Cycle 让奇观成为科研建筑，所以**零奇观等于整局游戏放弃这个
文明能力**（那个 170 回合的帝国到 T174 结束时是 0）；长城段落消耗的是 Builder 次数而不是城市产能，
这削弱了"我需要一支大军才有安全感"的论据；而单位和区域从同一条队列里出，所以每一个单位都是一座
没建成的区域。`CIVIC_CIVIL_ENGINEERING` 让 ram 和 tower 过时，那是**一个我们根本不带的工具箱的
截止日期**——攻城车队在每个时代都是答案，ram 和 tower 一个都不造（人类指令 2026-09-26：
不要 ram，用 Catapult）。

发展在同一个帝国上买到了什么：T59 到 T120 之间，改良 2 -> 25，科技 7.8 -> 28.1，金币每回合从未
低于 +17。要保护这个阶段。在这张地图和这套经济下，第一场战争属于攻城车队存在之后——现实地说是
T100-T120，而不是 T60。

**总督与大将军。**

这两者在之前的计划里都没有，而两者都免费地放大上面的一切。总督点数来自市政，不能廉价地重新分配，
所以每一个总督点数都应该买下你实际所处的阶段——而阶段结束时总督就该搬家。

- **发展时期把 Pingala（GOVERNOR_THE_EDUCATOR）放在人口最高的城市。** 基础：该城市 +15% 科技
  *和*文化。晋升 Researcher 再加 **+1 科技每人口**；Connoisseur 是它的文化版本。在一个 9 科技的
  帝国里，一座人口 4 的城市每回合加约 +4 科技，超过这个阶段任何可用的建筑。
- **把 Magnus（GOVERNOR_THE_RESOURCE_MANAGER）放在生产 Settler 的城市，并晋升到 Provision**：
  在那里训练的 Settler 不消耗人口点。他必须先就任——未就任的总督什么也不给——而且晋升必须在
  Settler 之前到位。
- **把 Liang（GOVERNOR_THE_BUILDER）放在生产 Builder 的城市。** 她的*基础*能力让在那里训练的
  每个 Builder **+1 次数**，不需要任何晋升，而 Zoning Commissioner 再加 +20% 建造区域的产能。
  一波 Builder 是游戏里最廉价的产出；这把它放大了。
- **战争临近或一座城市必须守住时用 Victor（GOVERNOR_THE_DEFENDER）。** Garrison Commander 给
  他的城市领土内防御的单位 +5 战斗力，并给 9 格内其他城市每回合 +4 忠诚度；Embrasure 让在那里
  建造的每个军事单位获得一次免费晋升。忠诚度才是让一座被占领城市倒戈的东西，所以一个总督加一个
  驻军是保住它的最廉价方式——远比为同一座城市打两次便宜。
- **Amani（GOVERNOR_THE_AMBASSADOR）是城邦工具。** 派驻到某个城邦时她算作 2 个使者，而 Puppeteer
  让他们翻倍。这就是不花使者代币也能守住宗主权的方式，而宗主权本身在城邦加成之外还每回合给
  +1 外交支持。

**Great General 是一种被动光环。不要激活它。** 只要将军还活着，它就给射程内的陆军单位 **+5 战斗力
和 +1 移动力**；Great Admiral 为海军单位提供同样的 +5/+1。`activate` 是一次*退役*——它消耗掉将军，
换取一次性的效果。把他停在大部队里，让攻城、近战和远程都待在光环内，只有在那一次性效果确实是
接下来十个回合所需时才让他退役。给每个攻击者 +5 战斗力不花产能，而且它让攻城车队破墙更快，
而破墙速度正是这局游戏里每一次突击的硬约束。

**征服。**

- 一次只打一个方向，先打最弱邻居的首都。
- **战争开始后，每座城市一个驻军。** 第二个站在城市格子上的单位所做的和第一个已经在做的一模一样，
  而前线却少了一个单位。超过那一个驻军的所有单位都属于前线：大部队、攻城车队、远程线。
  `metric(cities_over_garrison) > 0` 会让 `one-garrison-per-city` 规则失败。和平时期不同——
  那时驻军*就是*常备军，而规则对此保持沉默。
- **一个单位发现敌人——或遭到攻击——的那一刻：评估、集中、歼灭。** 不是互换：互换正是输掉消耗战的
  方式，因为敌人会治疗，而你拿不回那个单位。每次的流程：
  1. **评估。** 回合结果里的 `BATTLE ASSESSMENT` 区块会在敌方部队进入接触（三格以内）以及某个
     单位被击中时出现。它会列出每个敌人的类别、战斗力、HP、距离，以及你已有多少战斗单位在两格
     以内。行动之前先点名目标：那个能杀掉的（HP 低到射程内的单位足以收掉它），而不只是最近的那个。
  2. **集中。** 把附近站着的单位调入接触——对一个目标投入两三个攻击者就能在当回合杀掉它；
     一个攻击者只能互换。有敌人处于接触状态时，`metric(local_superiority) < 2` 会让
     `mass-on-contact` 失败，无论你有没有进攻。不要一个单位一个单位地送：T109-T111 的
     Battering Ram 和 Warrior 就是这样丢掉的。
  3. **歼灭。** 把每一个攻击者都集中到同一个目标上，让它在当回合掉到 0 HP。活下来的受损敌人每回合
     治疗约二十点，然后满血回来（`finish-the-wounded`）。然后保持部队集中，在回到原定目标之前把
     这群敌人剩下的解决掉——一支被打垮的野战部队是唯一能让下一座城市变便宜的东西。
  如果确实没有任何东西可以集中，就不要互换：撤到崎岖地形、一座城市里，或撤出敌人的触及范围，
  并在日记的 tactical 行里说明。规则在接触时触发；日记才是有意撤退被记录的地方。
- 在每一座被占领的城市留下驻军，并报告它的忠诚度。
- **忠诚度可以不打一仗就把城市拿回去，所以要守住你打下来的东西。** 一座远离核心、人口低、
  既没有总督也没有单位驻在其格上的被占领城市会叛乱成 Free City，然后不得不再围一次：实战中，
  Moscow 在 T112 被占领，到 T116 就成了 Free City——九次攻击和四个回合花在夺回我们自己的城市上，
  而 St Petersburg 还在等。回合结果带一个 `LOYALTY WARNING`，包含每座城市的忠诚度池、它的每回合
  压力、游戏判断它的走向，以及它的转化回合数——只有在城市正在失去忠诚度时才是叛乱倒计时，
  而在它增长时是回满池所需的回合数，所以两者会一起打印——流失时的下一个归属者、在任的总督、
  驻军，以及游戏自己的建议字符串；当一座忠诚度低于 50 的城市既没有总督也没有单位驻在其格上时，
  `hold-what-you-take` 会失败。答案是 `assign_governor`（调动一个是免费的）或者一个驻军——
  如果总督在前线更需要，那是一项要记录下来的决定，而不是可以跳过的。
- 沿新边界修建长城段落，能让被占领的土地便宜地守住。
- **永远不要和平。** 一旦宣战，战争只有在敌人的城市归你时才结束。绝不调用 propose_peace。
  拒绝每一次和平提议——无论是外交会话（get_pending_diplomacy，用 respond_to_diplomacy NEGATIVE
  回答），还是把和平与其他东西捆绑在一起的交易。这有意覆盖了 AGENTS.md 里那条常备建议，
  即和平通常胜过一次消耗战：指令就是战略，所以照它执行。
- 因为无路可退，宣战这个决定就是唯一重要的决定。只对一个邻居宣战，且只能是在已经就位的军队能够
  拿下它的城市时；并且只有在攻城车队和第一批增援都已就位之后。一场你打不完的战争，就是一场你
  绝不能开始的战争。
- 一场没打完的战争是纯粹的成本：战争疲劳压制产能，单位维护费继续在扣，而敌人仍然握着他还占着的
  每一座城市。如果前线停滞了，就修好前线——调攻城器、治疗、升级、增援——绝不用谈判把它换掉。
- 不要在拿下一次之后就停下军队。用最廉价的闲置单位驻守被占领的城市，然后让大部队直接开往下一座
  城市。
- 在宣战之前就把战争规划好：目标顺序、大部队集结的格子，以及已经排入队列的增援。

**城邦。**

- 城邦不是征服目标。统治胜利是拥有各主要文明的原始首都，所以拿下一个城邦对胜利毫无推进，
  而占领它会在所有认识它的文明那里换来好战怨恨。
- 一个你已经以宗主权掌握的城邦，活着比占为己有更值。Kabul 的宗主加成让你单位主动发起的战斗所获
  经验翻倍，此外还有军事型使者加成（每座拥有 Encampment 的城市 +2 建造单位的产能）和每回合
  +1 外交支持。吞并它等于为了一座城市删掉这三样东西。
- 反过来要守住宗主权：查 get_city_states 看对手的使者数量，让自己的使者代币保持领先。丢掉宗主权
  等于把整套加成送给一个对手，那比从来没拥有过更糟。
- 适配器没有暴露 Levy 动作，所以你不能自己征召城邦的军队。如果战争迫在眉睫，而一个你拥有宗主权的
  城邦有值得要的单位，就明确说出来，好让人类玩家能从游戏 UI 征召它们——被征召的单位为你作战
  30 回合，代价是金币。
- 只有在有明确理由时才攻击城邦：一个对手即将取得宗主权，而永久阻止比持有加成更划算；或者这座
  城市扼守当前战争真正需要的咽喉要道或资源。否则就别碰它。

**外国传教士。**

- 中国没有自己的宗教：一座 Holy Site 和每回合大约 1 点信仰买不了 Apostle 或 Inquisitor。
  **Condemn Heretic** 这个动作现在有了——`unit_action(action="condemn")` 实现的是游戏自身的
  `UNITCOMMAND_CONDEMN_HERETIC`，从一个**相邻**的军事单位发出的一条命令——但定义它的同一段文本
  也要求宣战（`LOC_UNITCOMMAND_CONDEMN_HERETIC_REQUIRES_WAR_DECLARATION`），所以它是一个战时
  动作。绝不要把计划建立在买不到的宗教单位上。
- 和平时期你完全碰不到宗教单位。`attack` 会回答 `ERR:NOT_AT_WAR`，`condemn` 会回答
  `ERR:REQUIRES_WAR`，而城市打击对它返回 `NO_ENEMY`。绝不单独为了传教士宣战。
- 在与它的所有者交战时，一个相邻的军事单位可以 `condemn` 它（一条命令，不消耗次数）或攻击它。
  把这当作顺手为之：一个单位、不追击、最多移动一格。一个传教士永远不值得让一个单位离开前线——
  而找到它们的清扫工作是任务 014 的事，不是军队的事。
- 真正的威胁是对手的宗教胜利，而不是一个传教士。每约 20 回合调用一次 get_religion_spread——
  这局游戏里它从未被调用过，所以宗教图景目前是未知的。某一个文明在其他每一个文明中都占多数，
  才是行动的触发条件；达不到这个程度的都是噪声。
- 攻击信仰收入，而不是传教士。Russia 的信仰来自它的 Lavra，所以在战争期间劫掠那座 Holy Site
  能从源头上截断这股水流，比任意数量的单个击杀都更值。
- 绝不购买宗教单位：一个传教士携带的是它被购买所在城市的主流宗教，而在中国那是外来信仰。
- 无视你自己城市被转化。这个计划里没有任何胜利条件依赖中国自己的宗教，所以不要把军事回合预算
  花在管控它上面。

**收到的提议。**

外交是在 AI 处理时到来的。`end_turn` 要么暂停并报告它（"Turn paused - AI diplomatic proposal
from ..."），要么直接阻断（"Cannot end turn: diplomacy encounter pending"）。针对你的宣战会被
自动关闭。

- **和平：一律拒绝。** 交易交给 respond_to_trade(other_player_id, accept=False)；会话交给
  respond_to_diplomacy(other_player_id, "NEGATIVE")。一个会话会进行 2-3 轮，所以每一轮都要回答
  直到它关闭——一个只答了一半的会话会一直阻断 end_turn。
- **要核实，绝不假定。** 宣战与和平动作可能报告成功，而引擎并没有改变状态：2026-09-20，T111 的
  宣战返回 WARN:WAR_UNCERTAIN，T122 的和平返回 ACCEPTED，但 Russia 在 T138 仍在提议和平——
  战争从未结束，而智能体一直当作战争已经结束来制定计划。任何宣战或和平动作之后，都要调用
  get_diplomacy 确认 WAR/和平 标志，然后才在此基础上做计划。
- 预期这个提议会重复：战争期间 AI 大约每 3 回合重新提议一次和平。拒绝很便宜；终结战争才是让它
  停止的办法。
- **一切不是和平的提议：按价值判断，绝不条件反射。**
 - 卖掉多余的奢侈品副本——奢侈品的第二份不给宜居度，所以用它换金币或 GPT。
 - 拒绝联合作战请求：第二条战线会破坏"一次只打一个方向"。
 - 拒绝要求、贡金，以及向第三方宣战的请求。
 - 只有在国内无法开采时才购买战略资源；你一宣战，那笔交易就结束了。
- 如果某个会话无法用工具关闭，就用纯文本说明，好让人类玩家在游戏窗口里回答它。不要让它拖住回合，
  也不要假定人类已经回答了它。

## Phase 1：定位

0. 在做任何事之前先调用 `mcp__civ6__get_game_status`：它说明到底有没有一局可以定位的游戏。
   `in_game`（它会报告回合数）意味着继续执行下面的步骤；`main_menu` 或 `leader_screen` 意味着
   必须先载入一个存档；`not_running` 意味着必须先启动游戏；`tuner_busy` 意味着另一个进程占着
   那条唯一的 FireTuner 连接，所以在它停止之前从这里发出的任何调用都不会成功——报告它，
   不要重试，也不要启动第二局游戏。绝不要从哪个调用失败的说辞里推断这些。
1. 在恢复一局已有的游戏或上下文被压缩之后，调用 `mcp__civ6__get_diary`。
2. 调用 `mcp__civ6__get_game_overview`，记录这局游戏的身份和回合数。
3. 收集单位、城市、相关地图区域、外交、胜利进度和通知。在周期性查询还没到期时，避免做宽泛的查询。
4. 构造一份唯一的规范文本快照。不要让 worker 独立查询实时游戏。

### 回滚之后，从游戏重建每一个事实

如果回合数比你上一次观察到的**更低**——人类载入了一个更早的存档，或者你从自动存档恢复了——
那么你掌握的关于这局游戏的每一个事实都已过时。棋盘状态没有版本号，也没有任何东西会警告你：
你记得在 (12,30) 的单位可能已经死了或在别处，城市的队列和人口可能不同，某个区域可能还不存在，
某场战争可能还没开始。依据那段记忆行动，就是走进一个已经不存在的局面。

第 3 步的"避免宽泛的周期性查询"在这里不适用。在采取任何行动之前，要完整地重新查询：

- `get_units`——每个单位：位置、HP、移动力、次数、晋升
- `get_cities`——每座城市：人口、食物盈余、队列、区域、住房、宜居度、被劫掠的格子
- 每座城市和每个单位周围的 `get_map_area`
- `get_game_overview`、`get_tech_civics`、`get_policies`、`get_governors`
- `get_diplomacy`、`get_victory_progress`、`get_trade_routes`、`get_religion_spread`、
  `get_empire_resources`、`get_world_congress`

读 `get_diary` 是为了**意图，绝不是为了状态**。写在你当前所处回合之后的条目描述的是一个已经不存在
的未来：从当前回合及之前的条目里取计划和推理，丢弃之后的一切，也不要引用一条过时的条目，
好像它是当前棋盘状态。

然后写一条日记，记录这次回滚——你来自哪个回合、你现在在哪个回合，以及你刚刚测得的全新基线——
这样下一个会话就不必重新发现上下文被重置过。

## Phase 2：委派分析

阅读 `prompts/workers/` 下的四个角色文件。用 `civ_advisor` 启动每个角色，并带上完整的规范快照和
它的角色说明。worker 没有工具。要求每个 worker 只返回符合 `contracts/worker-proposal.schema.json`
的 JSON。

`prompts/tactics/` 下的战术文件归各顾问所有——单位生产、发现即接触、遭受攻击、在敌人射程外集结、
队形与掩护、突击编成与射击纪律，以及战前分析，这些属于军事角色；再加上**战争与后方**，属于经济
角色。**worker 读不到它们：它没有工具，也没有文件系统。** 由你自己把与当回合匹配的一两个文件读出来，
把它们的文本粘贴进 `civ_advisor` 调用中，放在快照旁边；在调用里点名该文件，好让 worker 知道它被
要求遵守哪一份教条，并在 Phase 3 验证时把它的提案按该文件的禁令来约束。没有这次粘贴，worker 就会
凭一般知识提建议，那些战术文件等于不存在。

**战争进行期间，`economy-cities` 的简报里也要附上 `tactics/08-war-and-the-home-front.md`。**
正是这个文件回答了军队没有驻扎的那些城市该建什么——一座战争城市，其余每座城市做复利——而它的
报告区块（`WAR CITY`、`COMPOUND`、`SLOTS`、`CASH`、`UNITS`、`GOVERNORS`、`REVIEW`）正是战时
分工的决策依据。那个分工是粗放的，而且**在宣战时决定一次**，不每回合重新规划。

**去查机制，而不是猜，并把查到的东西粘贴出去。** `search_knowledge(query, k, doc)` 查询一个本地
索引，涵盖游戏手册、指令、规则文件和复盘，并给出源文件路径和行范围——读那些行，并把这段文字连同
简报的其余部分一起交给 worker。这是 worker 看到手册的唯一途径：它没有工具。每当决策取决于一条你
不确定的规则时就用它（治疗如何依赖补给线、支援单位能做什么、远程火力能否占领城市），并且当手册
与教条冲突时以手册为准——教条只是它的摘要。用 `python .tools/kb.py index [--source <path>]`
建立或刷新索引；它是每个检出各一份的。

**同时粘贴当回合自身的判断信号。** worker 什么都查不了，而这些正是决定结果的事实——T101-T116
围城的复盘显示它们每一个都起了作用：

- 上一次 `end_turn` 里的 `CHECK FAILED [id]` 行；
- `BATTLE ASSESSMENT` 区块（谁处于接触、什么能杀掉、我们有多少单位在射程内、克制提示）；
- 每个攻城单位的 `SIEGE POSTURE` 行（到最近敌人的距离、该敌人到掩护线的距离、到最近城市的距离）；
- `SIEGE PROGRESS` 区块，包括 `SIEGE STALLED`；
- `TAKE THE CITY` 区块，当它出现时：城市的 HP 池已空而占领仍未完成。它会点名那个格子和射程内的
  近战单位——一个继续对 0 HP 城市开火、而不是把那个单位移进去的提案是错的，而城市在等待期间
  每回合治疗约二十点；
- `skip_remaining_units` 打印的 `UNUSED ATTACK` 行。

然后在 Phase 3，用数字约束提案：与粘贴的 `BATTLE ASSESSMENT` 相矛盾、或引用了快照里不存在的单位的
提案会被拒绝，和格式错误的提案一样。

在支持后台执行时，先把所有适用的顾问都启动起来，再去收集它们的结果。每回合最多使用四个顾问。

## Phase 3：验证与综合

在下列情况下拒绝一个提案：

- 点错了游戏或回合；
- 不是合法的 JSON；
- 含有未知或被禁止的工具；
- 引用了不存在的单位或城市；
- 违反了一条明确的游戏状态前置条件；或
- 重复了一个动作标识符。

按这个顺序解决冲突：

1. 强制的结束回合阻断项
2. 城市或单位的存续
3. 被迫的战斗与战术安全
4. 生产、研究、增长与支出
5. 外交与胜利路线的推进
6. 探索与可选的优化

构建一份有序的动作列表。绝不为同一个单位或城市安排相互冲突的终局指令。

## Phase 4：作为唯一写入者执行

对每一个动作：

1. 确认当前回合仍然与计划相符。
2. 确认该动作尚未执行过。
3. 重新检查它的前置条件。
4. 调用变更工具一次。
5. 查询受影响的单位、城市或全局状态。
6. 把观察到的效果与预期效果比较。
7. 如果验证失败，停止依赖它的动作并重新规划。

绝不在未先查询状态的情况下重试一个超时的变更。

**复用你已经知道的东西。** 你这一回合发出的每一次查询都已经在你的上下文里。重复一次完全相同的
调用什么也买不到，还要花掉一整个往返：在一局实战的 105 个回合里实测，**所有调用中有 10% 是同一
回合内的完全重复**——延迟和 token 都花在重新学习片刻之前刚被告知的东西上。

- 这一回合早些时候得到的结果，对任何没有被变更触碰过的东西依然有效。不要为了确认一处改动就重读
  整个帝国。
- 只重新查询变更实际影响到的部分（第 5 步），并限定范围：确认移动过的那个单位，而不是再把每个
  单位查一遍。
- 在重复一次调用之前，先说出自第一次调用以来变化了什么。如果你说不出来，就用你已经有的答案。

## Phase 5：结束回合

**任何单位都不得在没有明确指令的情况下离开这个回合。** 一个没有指令的单位就是一个回合阻断项，
事后再处理它要多花一个往返：

- 优先选择有实际作用的指令。对一个原地不动的单位，`fortify` 严格优于 `skip`：它还会给予 +4 防御，
  并在设防期间治疗该单位。
- 对一个警戒某个方向的单位用 `alert`（敌人出现时自动唤醒），对一个恢复满血的单位用 `heal`，
  用 `automate` 让侦察兵继续探索。
- 对一个这一回合确实已经做完有用工作的单位使用 `skip`——一个没有可达任务的 Builder，一个目标
  已被覆盖的单位。`skip` 是"不应该行动"的正确答案，而不是默认答案。
- `skip_remaining_units` 是批量兜底，只在每一个本回合该行动的单位都已经有指令之后才使用。

**起飞前检查：在请求结束回合之前先做完这个回合的工作。** `end_turn` 会检查每一条 `EndTurnBlocking`
通知，如果还有任何东西需要做选择，它就会把回合弹回来，所以你每留下一件没做的事，就要多花一整个
往返。先自检：

**`10-TURN REVIEW` 到来时要读它。** 每逢第十个回合，`end_turn` 结果都会带一份：该窗口的实测差值
和每回合速率、十个回合前你自己的规划与假设被原样引回、指令里的突击前置条件与你实际拥有的单位对照、
空着的区域位、金币/回合的承载上限，以及对当前速率的向前推算。它以三个问题结尾，而这三个问题属于
那一回合的日记，而不是你的脑子里：这个窗口是否高效（带上数字）、下一个目标的哪个前置条件已就位、
哪个还缺，以及计划的完成回合是否仍然成立。一个什么也没买到的窗口逐个回合看都很正常；这个区块是
唯一能让它显形的地方。

**也要读 `CHECK FAILED` 行——并且预期其中会有一行消失。** 每个回合的结果都会带上
`prompts/checks/turn-checks.md` 中当前为假的每一条规则，对照你的军队和你的日记行来度量：
`CHECK FAILED [id]: ... (require: ...)`。一条标记为 `once: true` 的规则是一个目标，所以当你满足
它时，你会得到一次 `CHECK ACHIEVED [id] ... retired`，此后它再也不会触发——而同一回合会报告
`CHECK FILE PRUNED`，因为已达成的目标随后会从文件本身中被删除（在一份带时间戳的副本进入
`prompts/checks/archive/` 之后）。因此这个文件永远只列出仍然未完成的东西：一条规则从它里面消失
意味着它被做掉了，而不是检查坏了。

1. 有序列表里的每一个动作都已执行并验证（Phase 4 第 5-6 步）。
2. **调用 `get_units` 并阅读移动计数器。** 每个单位必须显示要么剩余移动力为零，要么是你刚刚下达的
   指令。不要假定你上一次 `unit_action` 覆盖了一切：本回合生产出来的单位，或者移动提前结算完的
   单位，仍然会留着移动力。
3. 没有任何城市的生产队列为空，也没有任何东西在等待决定：已完成的研究或市政、一个未晋升的单位、
   一个空着的政策槽、一个待创立的神系或宗教、一个时代奉献、一个未使用的使者，或一个未分配的
   总督点数。
4. 如果世界议会在本回合召开，就在结束之前登记选票——否则适配器会把回合弹回来并要求你投票。

然后，作为结束之前的最后一个动作，**无条件调用 `skip_remaining_units()`。** 它会让战斗单位设防，
然后跳过一切仍然有移动力的单位，所以它不花任何代价，并且它堵上了那个稳定地花掉十分钟的疏漏。
一个留着移动力的单位不只是把回合弹回来：游戏会拒绝推进，然后 `end_turn` 会一直轮询，直到它大约
九分钟的预算耗尽。

然后准备好全部五条非空日记反思——tactical、strategic、tooling、planning 和 hypothesis——并调用
`mcp__civ6__end_turn` **一次**。

`tooling` 反思带一行 **advisor trace**，形式如下：

```
advisor: military-map tactics/05-formation-and-screening.md -> 3 actions, 1 rejected (names a
unit not in the snapshot); economy-cities not called (no economy decision this turn)
```

而在没有运行任何顾问的回合里写 `advisor: none (<reason>)`。每个回合都要写它。它是委派分析确实
发生过的唯一持久记录：顾问不持有任何 MCP 工具，所以关于它们的一切都到不了遥测里，而日记正是后来
的复查（人类或智能体）用来回答"这套流程真的被遵循了吗，还是某一个会话自己把一切都做完了？"的
东西。

然后等待。不要自己去轮询回合数，也不要在第一次调用仍在进行时第二次调用 `end_turn`。`end_turn`
已经会通过轮询回合数来等待其他文明，直到回合推进——在慢回合里那是好几分钟，预算大约是九分钟。

阅读结果，弄清四件事中发生了哪一件，而只有第一件意味着你可以开始新的回合：

| 结果 | 含义 | 下一步 |
|---|---|---|
| 回合结果文本 | 回合已推进——其他文明完成了 | 从 Phase 1 开始新回合 |
| Blocker text | 还有东西需要做选择 | 解决它，然后**带着同样的反思**再次调用 `end_turn` |
| `HANG:` | 回合在预算内从未推进 | 服务器会自动恢复；行动前先核实状态 |
| `HANG RECOVERY FAILED` | 自动的 restart-and-reload 抛出了异常 | 游戏已经被重新启动，但没有载入任何存档。**由你自己调用 `restart_and_load('<save named in the message>')`。** 这是恢复，不是回退：被点名的那个存档是在*当前*回合开始时写入的，所以载入它恢复的是你本来就处在的局面。一条不许载入存档的常备指令并不禁止这件事——它禁止的是回到更早的回合。 |
| `GAME OVER` | 胜利或失败 | 停止 |

当它推进了，就把返回的事件当作下一个回合观察的开始。遇到游戏结束、身份不匹配、回合倒退或恢复
失败，立即停止。
